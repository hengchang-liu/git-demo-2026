【核心概念】
Git = 代码版本管理, 自动记录每次存档, 改坏了能回退
仓库(repository) = 被Git管起来的文件夹, 里面有隐藏的 .git/
三个区:
  工作区  = 你现在看到的文件(改了Git不知道)
  暂存区  = git add 之后, 挑哪些改动要存档(购物车)
  仓库    = git commit 之后, 永久存在 .git/ 里
类比: add=放购物车, commit=结账存档

⚠️ 重要区分:
  Ctrl+S = 文件存硬盘, Git不认作快照
  add+commit = Git存档, 能回退
  只Ctrl+S不commit的改动, restore/checkout会冲掉!

  git --version

第1步: 配置身份(只配一次)
============================================================
干啥: commit记录里显示是谁改的, 不是链接GitHub
  git config --global user.name "你的名字"
  git config --global user.email "你的邮箱"
  git config --global --list    ← 检查

第2步: 建仓库
============================================================
进到目标文件夹:
  cd "C:\...\51.CMakeGit\51.2Git"

把当前文件夹变成Git仓库:
  git init
  (显示 Reinitialized 是正常的, 因为之前建过)

============================================================
第3步: 第一个存档
============================================================
1. 写个文件 README.md
2. 看Git发现了啥:
  git status
3. 把文件放进暂存区:
  git add README.md
4. 真正存档:
  git commit -m "first commit: add README"
5. 看历史:
  git log

============================================================
第4步: 改文件再存档
============================================================
1. 打开README加一行字, 保存
2. 看Git发现了啥变化:
  git status
  -> modified: README.md
3. 看具体改了哪几行:
  git diff
  -> + 开头 = 新增(绿)
  -> - 开头 = 删除(红)
4. 存档:
  git add README.md
  git commit -m "change 1: add a line"
5. 简洁看历史:
  git log --oneline

============================================================
第5步: 分支 branch(重点)
============================================================
概念:
  master  = 主分支(正式版)
  feature = 开个平行副本试新东西, 不影响master
  merge   = 改好了合并回master

1. 看当前分支:
  git branch
  -> * master 表示在master上

2. 开新分支:
  git branch feature

3. 切到新分支:
  git checkout feature
  -> * feature 表示现在在feature上

4. 在feature上改README加一行 "on feature branch":
  git add README.md
  git commit -m "add line on feature branch"

5. 切回master:
  git checkout master
  -> 打开README, 刚才那行没了! 因为那是feature分支上的改动

6. 把feature合并回master:
  git merge feature
  -> 再打开README, 改动回来了

7. 删分支(合并完就可以删了):
  git branch -d feature

实际工作: 每个人/每个功能开个分支, 改完提PR合并回main

============================================================
第6步: 版本回退(三个命令区别, 重点!)
============================================================
前提: 所有commit快照都存在本地 .git, 不需要联网

【6.1 git checkout <哈希> - 参观旧版本, 只读】
  git checkout cbd6173
  -> 时光机, 跳到这个commit的快照看代码
  -> 此时处于 detached HEAD(游离HEAD), 不要在这里commit, 会丢提交
  -> 看完回最新: git checkout master
  ⚠️ 如果有未commit的改动, Git会报错不让切, 先commit或stash

【6.2 git reset --hard <哈希> - 真回退, 砍掉后面提交】
  git reset --hard bd0f4b1
  -> 分支指针直接移到这个commit, 后面所有commit从历史消失
  -> 适合: 本地自己玩, 还没push到远程
  ⚠️ 已经push到远程的分支别用! 团队会炸

【6.3 git revert <哈希> - 追加撤销提交, 团队首选】
  git revert 223ca00
  -> 不删历史! 新增一条反向commit, 抵消指定那次提交的改动
  -> 只撤销那次commit自己改了啥, 之前和之后的commit改动全部保留
  -> 历史链变长: ... -> 223ca00 -> revert-223ca00
  -> 适合: 已经push到远程、多人共用的分支

【关键区别一句话】
  checkout = 去旧版本参观, 看完能回来
  reset --hard = 直接退回去, 后面提交删掉
  revert = 新增一笔提交抵消那次改动, 历史完整保留

【revert例子(重点坑)】
  bd -> A(加line1 line2) -> B(加line3)
  git revert A
  -> 结果: 删掉 line1 line2, line3 保留! 文件并不是bd版本!
  -> revert不是回到某个时间点, 只是抵消那一笔改动

============================================================
第7步: git restore - 撤销未commit的改动
============================================================
⚠️ restore处理的是还没commit的草稿, 不碰历史!

【7.1 改了文件没add, 想放弃改动】
  git restore 文件名
  -> 文件恢复成上一次commit的样子
  -> 你刚才没存档的修改直接丢掉!

【7.2 已经add了, 想从暂存区拿出来(取消add)】
  git restore --staged 文件名
  -> 文件改动还在, 只是移出暂存区
  -> 不会删掉你写的代码

【和reset/revert区别】
  restore = 收拾未commit的草稿, 不改历史
  revert  = 已经commit了, 新增提交抵消
  reset   = 挪动分支指针, 删历史

============================================================
第8步: merge conflict 合并冲突
============================================================
什么时候出现:
  两个分支改了同一个文件的同一行, Git不知道听谁的

Git会在文件里标出来:
  <<<<<<< HEAD
  当前分支的内容
  =======
  要合并进来的分支的内容
  >>>>>>> feature

解决步骤:
  1. 打开文件, 手动改成想要的样子
  2. 删掉 <<<<<<< ======= >>>>>>> 这些标记
  3. git add 文件
  4. git commit -m "resolve conflict"

============================================================
第9步: .gitignore 忽略文件
============================================================
作用: 告诉Git哪些文件不要跟踪(编译产物、exe、IDE配置等)

在仓库根目录建文件 .gitignore:
  build/
  *.exe
  .vscode/
  .idea/
  Thumbs.db

⚠️ 文件已经被Git跟踪后再写进.gitignore无效, 要先git rm --cached

============================================================
常用命令速查
============================================================
  git status              看当前状态
  git add 文件             暂存改动
  git commit -m "说明"    存档
  git log                 看历史
  git log --oneline       简洁历史
  git diff                看具体改了哪几行
  git branch              看所有分支
  git branch 名字         开分支
  git checkout 名字       切分支
  git merge 分支名        合并分支
  git restore 文件        放弃未commit的改动
  git restore --staged 文件  取消add
  git revert 哈希         撤销某次提交
  git reset --hard 哈希   强制回退(慎用)

============================================================
常见坑
============================================================
- PowerShell里commit消息必须用双引号:
  错: git commit -m ''msg''
  对: git commit -m "msg"
- git init后显示 Reinitialized 是正常的
- 改了文件没commit就切分支, 改动会跟着走; commit了才留在分支上
- git log输出太长会进less分页器, 按 q 退出; 用 git log --oneline 不会卡
- git restore会丢掉未commit的修改! 想留住的内容必须先commit
- 只Ctrl+S不commit = 草稿, Git不认作存档
